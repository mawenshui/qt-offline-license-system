# Qt 离线授权系统：实现与构建指南

## 1. 已实现范围

- `QtLicenseIssuer`：Qt Widgets 签发端，支持创建/打开加密密钥库、单个授权、批量授权、读取授权。
- `QtHardwareCollector`：可交付客户机的图形硬件采集器，只输出散列指纹 `.qreq`。
- `qt-license-cli`：脚本化签发、采集、批量生成、验证和只读检查。
- `QtLicenseCore`：可嵌入 Qt 应用的静态库。
- Windows、Linux 硬件采集：CPU、主板、系统 UUID、系统盘、机器 ID；至少选择一个，支持 `all`、`any`、`threshold` 多选匹配。
- 授权类型：永久、固定到期、签发后有效时长、应用实际运行时长、固定到期与实际运行时长混合。
- 批量输入：UTF-8 CSV、JSON；支持整批永久授权。
- 密码学：Ed25519、XChaCha20-Poly1305、Argon2id、带密钥 BLAKE2b，均由 libsodium 提供。
- 离线时间保护：可信状态双副本、序号、MAC、时间回拨检查、单调运行时间累计。Windows 安装状态密钥使用机器级 DPAPI 保护；Linux 文件权限限制为当前用户。

协议和威胁模型见 [Qt离线授权系统详细设计.md](Qt离线授权系统详细设计.md)。

## 2. 目录

```text
LicenseSystem/
  core/          Runtime SDK 与签发公共核心
  issuer/        Qt Widgets 签发工具
  cli/           命令行工具及客户机硬件采集命令
  tests/         无测试框架依赖的端到端自检
  examples/      批量输入样例
  docs/          全部项目文档
  third_party/   Windows 离线构建所需 libsodium
  bin/           构建输出
```

## 3. 构建要求

- Qt 5.12.12 或后续 Qt 5/Qt 6，qmake，C++14。
- Windows：MinGW 32/64 位。仓库已包含 libsodium 1.0.22 对应预编译包。
- Linux：安装开发包及 `pkg-config`，例如 Debian/Ubuntu 的 `libsodium-dev`。

Windows：

```powershell
git clone https://github.com/mawenshui/qt-offline-license-system.git
mkdir build-LicenseSystem
cd build-LicenseSystem
qmake ..\qt-offline-license-system\LicenseSystem.pro CONFIG+=release
mingw32-make -j4
```

Linux：

```bash
git clone https://github.com/mawenshui/qt-offline-license-system.git
mkdir -p build-LicenseSystem && cd build-LicenseSystem
qmake ../qt-offline-license-system/LicenseSystem.pro CONFIG+=release
make -j"$(nproc)"
```

执行自检：

```powershell
..\qt-offline-license-system\bin\license-core-tests.exe
powershell.exe -NoProfile -ExecutionPolicy Bypass `
  -File ..\qt-offline-license-system\tests\real_world_cli.ps1
```

第一条执行全部核心断言。第二条调用正式 `qt-license-cli.exe`，使用本机真实硬件完成密钥库、采集、两种时长授权、读取、验证、篡改拒绝及批量签发闭环。脚本为每次运行创建随机产品标识，只清理该标识对应的临时授权状态和系统临时目录；Windows 需要允许读取 WMI 硬件信息并写入当前用户的本地应用数据目录。

## 4. 第一次使用

1. 在断网、受控签发机运行 `QtLicenseIssuer`。
2. 创建 `.qtkv` 密钥库。产品标识创建后不可变；口令至少 10 个 Unicode 字符，中文、英文、数字和符号均按字符计数。
3. 做两份离线加密备份，分别保管密钥库和口令。
4. 导出 `qtlicense_runtime_config.h`，编译进目标 Qt 应用；不要随应用分发 JSON 版本。
5. 客户机使用 `qt-license-cli collect ProductId device.qreq` 离线采集硬件请求。
6. 签发端导入 `.qreq`，填写客户、订单、功能和可选备注，选择至少一个硬件项及授权模式，生成 `.qtlic`。非永久授权可指定未来生效时间。
7. 将 `.qtlic` 放到目标应用约定路径，应用启动和运行中按接入指南验证。

永久授权使用独立的 `perpetual` 模式，不依赖系统时间，不用伪造超远到期日。

### 4.1 读取授权

“读取授权”默认打开“授权概览”，用中文显示验证结论、客户和订单、授权模式、UTC 起止时间、剩余期限、签发后有效时长或实际运行额度、功能、硬件匹配规则以及密钥标识。硬件指纹在概览中缩略显示，完整值保留在“完整技术数据”页。

- 默认读取只验签、解密并检查产品和内容结构，适合签发端读取客户授权；界面不会把它描述为“当前电脑可用”。
- 勾选“同时校验此电脑……”后，才执行当前电脑的硬件、有效期和离线防回拨状态检查。
- 已过期、尚未生效或硬件不匹配时，只要文件已通过验签和解密，概览仍显示可信授权内容，并单独标明不可用原因。
- 未通过签名、解密或结构检查的文件不展示载荷字段，避免把未认证数据当作可信内容。

### 4.2 时间输入与显示

签发页的生效时间和到期时间按签发电脑的本机时区输入，字段标签会显示时区名称和 UTC 偏移。生成时转换为 Unix UTC 时间戳写入授权文件，不把固定时区偏移写入协议，因此 Windows、Linux 和不同时区之间表示同一绝对时刻。

读取页同时显示本机时间、UTC 偏移和对应 UTC 时间。例如北京时间 `2026-09-22 16:08:01` 会显示为 `UTC+08:00`，并同时标明对应的 `2026-09-22 08:08:01 UTC`。这是同一时刻，不应再额外加减 8 小时。剩余期限始终按时间戳计算，不按界面字符串计算。

### 4.3 两种时长授权

签发页提供 1 周、1 个月、3 个月、半年和 1 年预设，也保留自定义秒数。1 个月按 30 天、3 个月按 90 天、半年按 180 天、1 年按 365 天计算。协议字段仍为 `max_runtime_seconds`，读取页和生成结果会把常用秒数转换成人类可读名称。

- `validity_duration`（签发后有效时长）：截止时刻为 `issued_at + max_runtime_seconds`。从签发完成开始流逝，即使授权文件从未加载也会到期。
- `runtime_quota`（应用实际运行时长）：只累计应用验证会话的实际运行时间。授权未加载、应用未运行或电脑关机时不消耗额度。
- `hybrid`：固定到期时间和应用实际运行额度任一达到即失效。

新 `validity_duration` 模式需要目标应用使用本次更新后的 `QtLicenseCore` 重新构建。既有授权以及 `perpetual`、`fixed_expiry`、`runtime_quota`、`hybrid` 模式保持兼容。

## 5. CLI

未设置 `QTLIC_PASSWORD` 时，CLI 从终端隐藏输入口令；离线自动化可临时使用环境变量：

```powershell
$env:QTLIC_PASSWORD = '使用密码管理器生成的长口令'
qt-license-cli.exe init issuer.qtkv ProductId
qt-license-cli.exe collect ProductId device.qreq
qt-license-cli.exe export-runtime issuer.qtkv runtime-config.json qtlicense_runtime_config.h
qt-license-cli.exe issue issuer.qtkv device.qreq customer.qtlic perpetual
qt-license-cli.exe batch issuer.qtkv batch.csv batch-output
qt-license-cli.exe verify runtime-config.json customer.qtlic device.qreq
qt-license-cli.exe inspect runtime-config.json customer.qtlic
Remove-Item Env:QTLIC_PASSWORD
```

`inspect` 验签、解密并读取授权，不做本机硬件和时间判断；`verify` 执行完整校验。生产应用不能只用 `inspect`。

## 6. 构建产物

- `bin/QtLicenseIssuer.exe`
- `bin/QtHardwareCollector.exe`
- `bin/qt-license-cli.exe`
- `bin/license-core-tests.exe`
- `bin/lib/libQtLicenseCore.a`
- `bin/libsodium-26.dll`

发布 Windows GUI 时，对 `QtLicenseIssuer.exe` 运行当前 Qt 套件的 `windeployqt --release`。目标业务应用也必须带上与其架构一致的 `libsodium-26.dll`。

```powershell
.\scripts\package-release.ps1 -Version 1.0.0
```
