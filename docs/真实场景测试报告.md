# Qt 离线授权系统真实场景测试报告

测试日期：2026-09-22
环境：Windows 64 位、Qt 5.12.12、MinGW 7.3、libsodium 1.0.22
范围：签发端、Runtime 使用端、硬件采集、离线状态、批量签发、异常和篡改路径

## 1. 测试结论

- Release 全量构建通过，正式 `exe` 与静态核心库已更新到 `bin/`。
- `license-core-tests.exe` 的 79 个断言全部通过。
- `real_world_cli.ps1` 的 14 个真实进程场景全部通过。测试使用本机多个独立硬件声明，不以伪造测试数据代替采集流程。
- `QtLicenseIssuer.exe`、`QtHardwareCollector.exe` 均能加载依赖、进入 Qt 事件循环。
- 授权正文、密文、密钥 ID、产品、硬件、时间状态或 Runtime 密钥被修改后均拒绝使用。

## 2. 模拟的完整业务流程

1. 创建带口令的 `.qtkv` 密钥库。
2. 从本机采集 machine-id、CPU、系统 UUID、硬盘等可用项，生成 `.qreq`。
3. 导出 Runtime JSON 和可编译进业务应用的头文件。
4. 签发“签发后有效时长”和“应用实际运行时长”授权。
5. 用正式 CLI 读取、验签、解密并执行产品、硬件、时间和离线状态校验。
6. 修改 `.qreq` 产品、授权密文和 Runtime 密钥，确认使用端分别拒绝。
7. 使用真实硬件散列批量签发两份授权，确认清单与授权文件完整生成。
8. 测试结束后清理随机产品 ID 对应的测试状态，不污染正式产品状态。

## 3. 修复的问题

### 3.1 一个硬件值可重复满足多个绑定槽位

原逻辑逐槽计数，同一类型和散列可能被重复命中。攻击者可利用重复槽位降低多硬件绑定强度。

修复：硬件匹配改为最大二分匹配，一个唯一 `(type, hash)` 声明最多满足一个槽位；载荷预检同时拒绝槽位内重复散列和无法达到最低命中数的绑定策略。覆盖重叠候选的最优匹配场景。

### 3.2 首次加载时允许系统时间早于签发时间

原逻辑首次使用会把过早系统时间钳制到签发时刻，没有明确拒绝。

修复：非永久授权在首次及后续验证中，只要系统时间比签发时间早超过 5 分钟，返回 `ClockRollbackDetected`。永久授权仍不依赖时钟。

### 3.3 批量文件名在跨平台时可能冲突

原逻辑对大小写敏感；`Case.qtlic` 和 `case.qtlic` 在 Windows 上会冲突，Windows 设备名也未预检。

修复：批量名称使用 Unicode case-fold 进行重复判断，并拒绝 `CON`、`PRN`、`AUX`、`NUL`、`COM1-9`、`LPT1-9`。任何一项失败都在正式输出目录创建前原子拒绝。

### 3.4 授权文件错误状态不准确

空文件被归为普通 I/O 错误，缺少版本字段的 `{}` 被误报为不支持版本。

修复：缺失、空文件、超限、格式损坏和明确的不支持版本分别返回 `FileMissing`、`MalformedContainer`、`FileTooLarge`、`MalformedContainer`、`UnsupportedVersion`。

### 3.5 错误产品被误报为签发证书无效

修复：证书产品范围不匹配和载荷产品不匹配统一准确返回 `ProductMismatch`，证书签名损坏仍返回 `IssuerCertificateInvalid`。

### 3.6 单授权输出存在检查后覆盖窗口

修复：授权先写入同目录唯一临时文件，再用不覆盖的原子重命名提交。目标已存在时保持原文件不变。签发后自检从只比较授权 ID 提升为比较完整规范化载荷。

### 3.7 CLI 输入边界不足

修复：Runtime 解密密钥长度在使用前验证；`verify` 强制 `.qreq` 产品与 Runtime 产品一致；未通过认证时不再输出默认空载荷，避免把未认证字段误认为可信内容。

### 3.8 错误诊断不可操作

修复：Release 自检直接向标准错误输出失败原因；状态目录创建失败会返回具体目录。新增可重复运行的真实 CLI 测试脚本。

## 4. 核心异常和攻击场景

- 授权文件不存在、为空、JSON 损坏、版本不支持、超过大小上限。
- 根公钥错误、解密密钥缺失或长度错误、产品不匹配。
- 授权密文、`ekid` 头字段、密钥库密文被修改。
- 缺少功能权限、硬件不匹配、同一硬件重复占用多个槽位。
- `not_before` 边界、签发后有效时长到期边界、首次使用前回拨。
- 实际运行时长按真实约 1.1 秒会话记账并耗尽额度。
- 离线状态单副本损坏可恢复，双副本损坏拒绝；状态存在但安装密钥丢失时拒绝。
- 目标授权文件已存在时不覆盖；批量名称大小写冲突和设备名在预检阶段拒绝。

## 5. 仍然存在的纯软件离线边界

这些限制不能靠继续混淆代码彻底消除：

- 首次使用前没有可信外部时钟。当前实现能拒绝“早于签发时间”的明显回拨，但攻击者仍可把时间设置为签发后、到期前的可信区间。永久离线时无法证明真实世界时间已经前进。
- 若攻击者能完整回滚系统镜像、DPAPI 状态和授权状态，纯软件无法可靠区分旧快照与当前状态。更强保证需要 TPM/安全芯片、可信 RTC 或在线时间/授权服务之一。
- Runtime 必须持有产品解密密钥。拥有管理员、调试器或进程内代码执行能力的攻击者最终可能提取密钥或绕过分支。多点校验、控制流保护和混淆只能提高成本。
- 本轮实际编译和进程测试在 Windows 完成。Linux 路径已保留并受核心测试覆盖，但发布前仍需在目标 Linux 发行版执行原生构建、硬件采集、文件权限和状态回拨测试。
