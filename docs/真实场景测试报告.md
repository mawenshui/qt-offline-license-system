# Qt 离线授权系统 v1.0.1 全流程测试报告

测试日期：2026-09-23

环境：Windows 64 位、Qt 5.12.12、MinGW 7.3、libsodium 1.0.22

范围：Release 构建、核心、签发器 UI、硬件采集、CLI、离线状态、批量签发、发布包、Runtime SDK、异常和篡改路径

## 1. 结论

- `tests/full_flow.ps1 -Version 1.0.1` 返回退出码 `0`，输出 `ALL FULL-FLOW SCENARIOS PASSED`。
- Release 全量构建、核心回归、签发器 UI 状态冒烟均通过。
- 真实 CLI 的 14 个进程场景通过，使用本机硬件采集结果完成闭环。
- 两个发布 ZIP 的 SHA-256 与 `SHA256SUMS.txt` 一致，压缩包敏感文件扫描为零。
- 解压后的签发器和采集器可进入事件循环；发布包内核心测试可运行。
- 解压后的 Runtime SDK 可在独立目录完成 qmake 构建并运行冒烟程序。

## 2. 自动化覆盖

1. 校验 `core/version.h` 与目标版本一致。
2. qmake Release 全量构建所有应用、核心测试和 UI 测试。
3. 执行 `license-core-tests.exe`，覆盖协议、密钥库、硬件匹配、时间状态、审计链和 Runtime 兼容性。
4. 以 Qt offscreen 平台执行 `issuer-ui-smoke-tests.exe`，验证主页面、锁定状态门控、目标 Runtime 和即时校验。
5. 创建临时密钥库，采集真实硬件，导出 Runtime 配置，签发、读取、验证、篡改并执行批量原子发布。
6. 生成应用包、Runtime SDK 包和 SHA-256 清单。
7. 扫描 ZIP，拒绝 `.qtkv`、`.qtlic`、`.qreq`、`runtime-config.json` 和 `qtlicense_runtime_config.h`。
8. 解压应用包，运行内置核心测试并启动两个 GUI。
9. 解压 Runtime SDK，在独立构建目录编译并运行最小程序。
10. 执行 `git diff --check`。

## 3. P0 专项场景

- 密钥库锁定时导出、单个签发、批量签发不可点击。
- 目标 Runtime 选项为 `1.x`；授权格式 v1 与 Runtime SDK 1.x 兼容，错误系列被拒绝。
- 空客户、无效输出路径等可预判输入在提交前显示并标记。
- 审计事件可连续写入并验证；修改既有记录后完整性验证失败。
- 审计 JSONL 不出现 `password`、`private_key`、`decryption_key` 或原始硬件字段。
- 备份流程只复制加密 `.qtkv`，比较 SHA-256，并通过正式 `KeyVault::open` 恢复核对。
- 签发确认只显示业务摘要，不显示任何密钥材料。

## 4. 真实业务与攻击场景

- 创建加密密钥库，采集 machine-id、CPU、系统 UUID、硬盘等可用项并生成 `.qreq`。
- 导出 Runtime JSON 和可编译头文件；签发“签发后有效时长”和“实际运行时长”授权。
- 执行产品、硬件、功能、有效期、运行额度和离线状态校验。
- 修改请求产品、授权密文和 Runtime 密钥后拒绝使用。
- 同一硬件声明不能重复满足多个绑定槽位。
- 明显早于签发时间的首次加载返回 `ClockRollbackDetected`。
- 单个授权目标存在时不覆盖；批量名称大小写冲突、Windows 设备名或任一失败均在发布前原子拒绝。
- 空文件、超限、畸形和不支持版本返回对应状态；未认证数据不作为可信载荷展示。
- 离线状态单副本损坏可恢复，双副本损坏或安装状态密钥丢失时拒绝。

## 5. 已知边界

- 首次使用前没有可信外部时钟；纯离线软件无法证明真实世界时间已越过某个点。
- 同时回滚整机镜像、系统保护状态和授权状态时，纯软件无法可靠识别旧快照；更强保证需要 TPM、安全芯片、可信 RTC 或在线可信时间。
- Runtime 必须持有产品解密密钥；管理员/root、调试器或进程内代码执行最终可能提取密钥或绕过分支。
- 本报告的完整构建和进程测试在 Windows 完成。Linux 路径受核心测试覆盖，但正式 Linux 发布仍需在目标发行版执行原生构建、硬件采集、权限和状态回拨测试。
