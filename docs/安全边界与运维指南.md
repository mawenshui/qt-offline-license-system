# 安全边界与运维指南

## 必须接受的边界

纯软件、永久离线、无可信硬件三项同时成立时，无法获得不可伪造的绝对 UTC。当前实现能检测常规回拨、运行时冻结和单个状态副本回滚；不能可靠抵抗管理员/root 回滚整机快照、修改内核计时源或补丁掉授权判断。

因此“到期时间准确”含义是：在操作系统和本地持久状态未被攻击者同时完全控制时，使用墙上 UTC 与进程单调时间取最大推进值，系统时间回拨不会让授权重新有效。若要求抵抗整机快照，必须增加 TPM 单调计数器、安全芯片、外部硬件锁或在线可信时间源。

## 密钥分级

- `.qtkv`：含根私钥、签发私钥、产品加密密钥。最高敏感级，仅放受控离线签发机。
- `qtlicense_runtime_config.h`：含根公钥和产品解密密钥。只编译进目标应用；可被逆向，不具备签发能力。
- `.qtlic`：可公开传输，但不要把其中客户元数据当秘密。
- `.qreq`：含散列后的硬件标识，仍按个人/设备标识数据管理。

## 备份和恢复

1. 每次建立产品密钥库后，做至少两份加密离线备份。
2. 密钥库文件和口令分开保管；记录产品 ID、密钥 ID、创建人和时间。
3. 使用签发器“复制加密备份”复制 `.qtkv` 并核对 SHA-256，不导出明文私钥。
4. 使用“验证备份可恢复”打开备份，核对产品、密钥 ID 和根公钥；定期在隔离机生成测试授权并用已发布 Runtime 验证。
5. 私钥疑似泄漏时停止签发并发布带新根公钥的应用版本。旧应用内置旧根公钥，纯离线场景无法远程吊销。
6. 授权状态损坏时不得直接删状态；签发替换授权，并按运维流程增加 `state_epoch`。

## 签发端状态与审计

- 密钥库锁定时，签发、批量签发和 Runtime 配置导出必须保持禁用。
- 密钥库解锁后 10 分钟自动锁定；最后 60 秒进入告警状态。离开工位前应主动锁定。
- 当前授权格式 v1 只面向 Runtime SDK 1.x；签发前兼容预检失败必须停止。
- 审计日志默认位于当前用户本地应用数据目录的 `audit/audit-YYYY-MM.jsonl`。
- 每条审计记录包含前序哈希和自身哈希。定期使用签发器验证日志；验证失败时保留原文件、停止依赖该日志做合规结论并调查副本差异。
- 审计仅记录操作元数据、结果、文件路径和 SHA-256，不记录密钥、口令、原始硬件值或完整解密载荷。

## 发布检查

- 确认 Release 构建和目标架构一致。
- 确认业务应用不包含 `.qtkv`、口令或签发私钥。
- 对业务 EXE/ELF 和安装包做签名/哈希归档。
- 在干净 Windows、Linux 机器验证：缺少授权、错误产品、硬件变化、密文篡改、过期、回拨、状态损坏、永久授权。
- 将授权失败原因写入本地审计日志时，过滤密钥和原始硬件值。
- 从仓库根目录执行 `.\tests\full_flow.ps1 -Version 1.0.1`，确认两个 ZIP、`SHA256SUMS.txt`、敏感文件扫描、解压启动和 Runtime SDK 独立构建全部通过。
