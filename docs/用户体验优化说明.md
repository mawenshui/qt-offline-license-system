# 用户体验优化说明

本文从实际使用者视角记录当前体验、v1.0.1 已完成改造和后续优先级。目标是让离线授权流程易学、少出错、可恢复、可审计，同时不扩大密钥暴露面。

## 1. 用户与核心任务

| 用户 | 主要任务 | 最关心的问题 |
| --- | --- | --- |
| 签发管理员 | 保管密钥、创建授权、处理续期与补发 | 是否会误签、泄露密钥或覆盖已有数据 |
| 客户机操作员 | 采集硬件信息、带回申请文件、安装授权 | 是否需要理解专业字段，文件是否包含隐私 |
| 应用开发者 | 集成 Runtime SDK、处理授权状态 | 接口是否稳定，错误是否能指导用户恢复 |
| 售后与审计人员 | 读取授权、定位无效原因、核对签发记录 | 能否快速得到人类可读结论和可靠证据 |

## 2. 当前用户路径

1. 开发者把运行端配置和 Runtime SDK 编译进产品。
2. 签发管理员按首次使用向导创建密钥库、复制加密备份并验证可恢复性。
3. 客户机操作员运行采集器，使用中文友好名称选择项目并生成 `.qreq`。
4. 签发管理员导入请求，设置客户、期限、功能、硬件规则和目标 Runtime 版本。
5. 签发器即时检查输入并显示确认摘要，确认后生成 `.qtlic`、自验证并写入审计事件。
6. 客户安装授权；目标应用在启动、检查点和关键功能入口验证。
7. 售后人员读取中文授权概览；审计人员可验证 JSONL 日志哈希链。

## 3. v1.0.1 已完成改造

### 3.1 视觉与信息表达

- 签发器与采集器使用统一墨蓝、暖灰和铜色工业控制台主题。
- 页面标题、说明、信息块、主次按钮、表格和状态栏形成一致层级。
- 面向用户的配置名使用中文，例如“系统 UUID”；内部字段名只在悬浮提示、技术数据页或文档中出现。
- 启用 Qt 5 高 DPI 适配，增加表格交替行、整行选择和可访问名称。

### 3.2 P0：误操作和安全风险控制

| 项目 | v1.0.1 行为 | 自动化证据 |
| --- | --- | --- |
| 首次使用向导 | 四步说明密钥库、Runtime 配置、硬件采集和签发流程；可跳过，也可从菜单重开 | GUI 启动与对象状态冒烟 |
| 操作状态门控 | 密钥库锁定时禁用导出、单个签发和批量签发；显示 10 分钟自动锁定倒计时，最后 60 秒告警 | `issuer-ui-smoke-tests` 验证锁定状态 |
| 表单即时校验 | 产品、客户、输出路径、时间、硬件绑定、载荷和 Runtime 兼容性在签发前汇总，首个错误获得焦点并标红 | UI 状态测试及核心载荷回归 |
| 签发前确认摘要 | 展示产品、客户、模式、功能、绑定规则、目标 Runtime 和输出路径；默认按钮为取消 | UI 交互实现与发布包启动测试 |
| 密钥备份检查 | 只复制加密 `.qtkv`，拒绝覆盖并比较 SHA-256；验证时用口令打开备份并核对产品、密钥 ID 和根公钥 | 备份路径复用 `KeyVault::open`，核心密钥库测试覆盖 |
| 审计日志 | 记录 UTC、操作、结果、产品、业务主体、文件路径和 SHA-256；每条包含前序哈希和记录哈希，可检测修改 | 核心测试覆盖写入、验证、敏感字段扫描和篡改拒绝 |
| 版本兼容预检 | 当前签发格式 `version: 1` 只允许目标 Runtime SDK `1.x`，不兼容时阻止签发 | 核心兼容性成功/失败断言 |

审计日志默认位于当前用户本地应用数据目录的 `audit/audit-YYYY-MM.jsonl`。日志不记录口令、私钥、产品解密密钥、原始硬件序列号或完整解密载荷。

## 4. 后续优化优先级

### P1：提高效率和定位速度

| 优化项 | 用户痛点 | 建议方案 | 验收标准 |
| --- | --- | --- | --- |
| 授权模板 | 同类客户重复填写模式、功能和硬件策略 | 保存不含客户隐私和密钥的模板 | 套用后仍确认客户和设备信息 |
| 功能项目录 | 自由文本易产生拼写差异 | 从产品配置读取功能名、中文说明和互斥关系 | 未知功能明确警告，保留受控高级输入 |
| 硬件绑定健康度 | 用户不清楚硬件变更风险 | 根据选项提示稳定性和预计容错能力 | 只提示，不静默修改策略 |
| 请求导入预览 | 难以确认设备和产品是否正确 | 显示产品、采集时间、硬件项目、请求哈希和重复项 | 产品不匹配时阻止继续 |
| 批量预检报告 | 文本结果定位失败行成本高 | 表格显示成功、警告、失败和原始行号 | 任一失败仍保持原子发布，可导出报告 |
| 签发完成回执 | 文件生成后仍需人工核对 | 展示自验证后的许可证编号、期限、路径和 SHA-256 | 不使用未签名前表单值充当结果 |
| 售后诊断建议 | 普通用户不理解状态码后的恢复动作 | 为过期、硬件不匹配、回拨等状态给出安全建议 | 不承诺绕过校验，技术详情可展开 |
| 最近任务 | 反复选择目录影响效率 | 只保存最近目录和非敏感偏好 | 可一键清除，不保存口令或文件内容 |
| Runtime SDK 接入体验 | 当前以 qmake 和源码示例为主 | 补充 CMake、状态文案映射和最小 GUI 示例 | Qt 5/6 的 qmake 与 CMake 示例均由 CI 编译 |

### P2：完善长期生命周期

| 优化项 | 价值 | 约束 |
| --- | --- | --- |
| 补发和续期关联 | 从新授权追溯原许可证 | 只记录编号和业务原因，不复制旧密钥材料 |
| 离线撤销清单 | 受控撤销丢失设备或违规授权 | 清单必须签名，并设计离线分发和过期策略 |
| 签名密钥轮换 | 支持长期运营和密钥事件处置 | Runtime 同时信任当前及过渡公钥，明确退役时间 |
| 产品与客户目录 | 减少多人签发输入差异 | 本地加密存储，不引入默认联网账户系统 |
| 多语言与无障碍模式 | 支持海外交付、键盘和高对比度用户 | 文案与状态码分离，完成键盘和缩放测试 |
| 离线介质校验 | 降低 U 盘拿错或损坏风险 | 展示并校验哈希，不把普通哈希描述成签名 |

## 5. 不直接加入的功能

- 不把签发器改成默认联网服务；这会扩大私钥暴露面。
- 不提供私钥明文导出；备份只复制加密密钥库并执行恢复验证。
- 不采集或保存完整硬件序列号；匿名指纹满足匹配需求。
- 不把完整授权载荷写入审计；只保留必要元数据和文件哈希。
- 不用界面隐藏纯软件授权的安全边界；管理员/root、调试和整机快照攻击仍需明确说明。

## 6. 下一轮建议范围

优先实现“请求导入预览 + 批量预检表格 + 签发完成回执”。三项复用现有校验和自验证结果，不改变协议或密码学，实现风险较低，能明显缩短高频签发与售后定位路径。

## 7. 产品体验验收指标

- 新用户首次完成“采集—签发—读取”闭环不超过 10 分钟。
- 可预判的关键表单错误在提交前发现率达到 100%。
- 签发结果始终自验证，批量任务不存在部分发布。
- 主要操作可用键盘完成，125%–200% 缩放下无关键文本截断。
- 中文主界面不直接暴露未解释的内部键名；技术字段可在一层交互内找到。
- 日志、设置、请求和发布物不包含签名私钥、口令或明文原始硬件值。
